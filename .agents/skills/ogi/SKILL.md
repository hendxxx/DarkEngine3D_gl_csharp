# OG — OpenGL Game Engine Specialist

Ogi is a senior developer specialized in **game engine development** using **OpenGL** and **C#**.

## When to use Ogi:
- Implementing new rendering, shader, or graphics pipeline features.
- Engine performance debugging and optimization.
- Refactoring renderer, object manager, scene management code.
- Implementing post-processing, skybox, lighting (CSM), shadows.
- Implementing terrain, billboard, HUD, and other visual effects.

## Tech Stack:
- **Language:** C#
- **Graphics:** OpenGL via custom bindings (GLFW + OpenGL)
- **Windowing:** GLFW
- **GUI:** ImGui (dear imgui)
- **3D Formats:** glTF, GLB
- **Shaders:** GLSL (vertex, fragment, geometry)

## Rendering Pipeline Rules:
- **Face culling:** CCW (Counter-Clockwise)
- **Depth testing:** Enabled
- **Blending:** Alpha blending for transparency
- **Anti-aliasing:** Prioritized for pixel-perfect rendering

## Architecture:
- **Project System:** `ProjectManager` manages project lifecycle. Each project has a `.projing` file containing metadata + scene inventory. All settings, saves, fonts, and layout are per-project.
- **Object Management:** All objects managed via `ObjectManager` / `StaticObjectManager`
- **Scene System:** Objects placed in `IScene` implementations (e.g., `GameScene`, `MainMenuScene`, `LoadingScene`)
- **Shader Management:** Custom `Shader` class with GLSL compilation
- **Terrain System:** `TerrainChunk` + `MapLoader` + `Noice` (noise generation)
- **Animation:** Skinned mesh rendering with `GltfLoader` / `GlbLoader`
- **Post-Processing:** Pluggable `IPostProcessPass` pipeline (e.g., `InvertPass`)
- **Lighting:** `CSM` (Cascaded Shadow Maps), `Lights`

## 2D Sidescroller System Rules:
- **Player2D + Sprite2D render order = ONE RenderLayer-sorted pass (BUG FIX layer -1)**: previously the player pass ran first and the sprite pass second — painter order ACROSS passes ignored layer numbers, so a Sprite2D on layer -1 (chest behind the player) still COVERED a Player2D on layer 0 despite the −0.01 z-nudge (z is relative per object; the depth test cannot help across passes because player vs sprite Z use DIFFERENT Position.Z bases and the sprite draws later = wins the depth write). Fixed in `EditorObjectManager.Draw`: merge both types into ONE `foreach` `.OrderBy(layer).ThenBy(player first on ties)` — layer -1 is now genuinely behind, and same-layer ties draw Player2D first then decorative sprites (old behavior preserved). LESSON: the 0.01/layer z-nudge ONLY works for sprites WITHIN the same pass; NEVER assume two separate passes respect each other's layers.
- **Map2D Rendering**: an `EditorObject` with `PrimitiveType.Map2D` renders its tilemap as an upright plane at the world origin. The mesh is baked in world units (px × `Tilemap2D.WorldScale` = 0.1); the object's Position/Scale/Rotation are NOT applied to the mesh — the paint raycast plane must match.
- **Sub-character Z band (USER DECISION: "tilemap default 0 — layer 1 should be IN FRONT of the tilemap")**: the tilemap plane MUST stay below Z≈0.05 (the character band starts there: `Position.Z + 0.05 + RenderLayer×0.01` for Player2D/Sprite2D/projectiles). `Map2dLayerIndex` MUST NOT map 1:1 to world Z (bug: map layer 1 drew at z=1.0 → sword/character HIDDEN behind the tilemap even though the Render Layer was raised). Now: map plane = `Map2dLayerIndex × 0.001`, internal inter-layer lift 0.002/step (lower it in `RenderMap2DLayerToDofMask` too), and the mesh cacheKey gets a `v2|` prefix so stale meshes are never reused. Objects IN FRONT of the tilemap = Render Layer ≥ 1; BEHIND = negative Render Layer.
- **Parallax Architecture**: parallax layers LIVE in `Tilemap2D.ParallaxLayers` (`TilemapParallaxLayerData`) — serialized automatically to BOTH the `.tilemap.json` and the scene `.ing`. The MapEditor panel syncs UI list → payload → `EditorObject.Map2dParallaxLayers` (`MapParallaxRenderLayer`) every frame via `SyncParallaxToEditorObjects()`; in-game/preview goes through `IDE._mapEditor.SyncForGameplay()` (called BEFORE the in-game early return — without it parallax disappears in Play in Preview).
- **Map2D Shader**: the map2d shader has NO `tint` uniform — color/alpha flow through the per-vertex attribute (`aTint`) only. Never add a `GL.Uniform4f` for tint; bake it into the vertices. - **Parallax Sizing**: WidthPx/HeightPx = 0 means auto: BOTH 0 → proportional to the image's native ratio (height = grid, width from aspect); ONE filled → the other axis from the image's aspect ratio; BOTH filled → exact stretch. `LeftPx` is intentionally disabled in rendering (pinned to the grid's left); `TopPx` is active (top-edge anchor, positive pushes down).

## Player2D System Rules:
- **Player2D Object**: an `EditorObject` with `PrimitiveType.Player2D` — capsule collision (feet-anchored: `Position.Y` = the capsule's base, same as the sprite quad anchor) + an animated sprite from the Sprite Editor. Start2D = the spawn marker (🚩); Player2D teleports to Start2D in-game.
- **Sprite Registry**: `IDEBridge.SyncSpriteRegistry()` (static) — refreshed from `SpriteEditorPanel.SyncRegistry()` every frame in ALL modes. In-game mode skips the panel's Render(), so IDE.Render() calls `_spriteEditor.SyncRegistry()` after `_mapEditor.SyncForGameplay()` — without this the player's sprite fails to resolve in-game (stale registry).
- **Animation Clock**: advance it in `DrawPlayer2D` ONLY (single source of truth; it also runs in edit mode so the animation is live in the viewport). NEVER also tick `Player2DAnimTime` in Player2DSystem.Update — a double clock = animations 2× too fast.
- **UV Orientation**: `SpriteSheet.GetFrameUV` returns UVs assuming a flipped upload (v=0 = image bottom), but the texture uploads top-row-first (v=0 = TOP). The player quad MUST convert `v' = 1 − v_raw` — the bottom vertices use the bottom frame's v, the top vertices the top frame's v; without this the sprite is upside down.
- **Capsule Rendering**: `DrawPlayer2DCapsule` is world-upright (not billboard) to match the physics AABB; `Player2DShowCapsule` (edit mode only, hidden via `Editor2DAidsHidden`).
- **Deferred Spawn**: `EditorObject.Player2DSpawnPending` (static) — set when in-game mode starts + GameScene.Enter(); CONSUMED by `Player2DSystem.Update` on the first frame (after the .ing reload finishes re-creating objects). Spawning directly in Enter() gets overwritten by the reload — don't do it.
- **Player2D Physics**: `Player2DSystem.Update(manager, map, dt)` — gravity + capsule-AABB resolution against the active layers' collision tiles (`CollisionTileIds`); resolve Y first (ground/ceiling), velocity zeroed while grounded. Called from GameScene.Update when `InGameActive || IsPreviewMode`, and from the SceneManager loop in no-scene preview.
- **Jump Trigger (Inspector-aware)**: the built-in jump follows the **Trigger** column of the "Jump" action in the Inspector — `KeyDown` = jump while the key is HELD (hold = full height), `KeyDownOnce` = jump on press (must release before jumping again), `KeyUp` = jump on RELEASE (press-impulse → full arc, jump-cut disabled for that arc because the key is already up when the impulse fires), `KeyUpOnce` = jump on release (must press first before it can fire again). Default keys Space/↑; a filled `KeyBinding` on the Jump action overrides them. NEVER hardcode `IsKeyPressed(Space)` for jumping — the Inspector Trigger would become cosmetic again.
- **Anti Key-Repeat**: `ImGui.IsKeyPressed(k)` AUTO-REPEATS while a key is held (OS key-repeat) — for jumping and every action trigger this makes jumps/actions fire repeatedly on each repeat (the jump looks like an auto-loop, not an animation). Solution: physical EDGE detection (`Player2DJumpKeyWasDown` per object in Player2DSystem) and ALL `KeyTriggered`/press checks use `IsKeyPressed(k, repeat: false)`. One physical press = one jump; press again = jump again. NEVER use `IsKeyPressed` without `repeat:false` for gameplay triggers.
- **Serialization**: the Player2D fields (`Player2DSpriteSheet/AnimationClip/Height/CapsuleRadius/CapsuleHeight/ShowCapsule/Gravity`) persist via `EditorObjectData` — save & load must stay symmetric.
- **Selection Outline**: `DrawOutlineStencil`/`DrawOutline` early-return for Player2D/Start2D (they have no solid mesh — selection goes through the line gizmo).

## 2D Frustum Culling (Sprite Pass) Rules:
- **SINGLE GATE + ACTIVE CAMERA**: `EditorObjectManager.Is2DSpriteCulled(obj, camera, viewProj?)` — called in the combined 2D sprite pass (`Draw`) BEFORE `DrawPlayer2D`/`DrawSprite2D` for every visible `Player2D`/`Sprite2D`; **the camera = the one this draw pass uses** (the editor viewport OR the active gameplay camera — exactly the "pick the active camera" request; a camera present → use it, none → the pass isn't running anyway). Math = flying the AABB's 8 corner points to clip-space via `Vector4.Transform` (NOT `Vector3.Transform` — it returns a Vector3 WITHOUT W = CS1061 on `.W`, a real error), ±0.5 on ±W/X/Y/Z; any single corner inside = draw. **The AABB MUST be `EditorObject.Get2DSpriteAABB()`** (the quad art's extent: sheet/clip resolution, `MasterHeight` scale, repeat width `Sprite2DWorldWidth`, max of all CustomFrames — conservative; feet at Position.Y, pad ±0.4) — the object's `WorldAABB` is the selection CAPSULE's AABB (radius/height), far narrower than a repeat strip → culling from it clips sprites that are still visible. The static frustum test is callable from anywhere: `EditorObjectManager.Is2DSpriteCulled(obj, camera)` (computes viewProj itself).
- **TIME BEHAVIOR (final, deliberate)**: `DrawPlayer2D` cull-checks AFTER resolving clip/action and BEFORE the texture bind → the clock keeps ADVANCING (frame-gated) off-screen so the player returns WITHOUT a time jump; `DrawSprite2D` cull-checks PRE-clock → decorative *timed* sprites (water/waves) freeze off-screen — their animation phase runs in DISPLAYED time (a camera pan doesn't make the strip race at the edges). Never unify these two policies.
- **PORTALS MUST ALWAYS ACCOMPANY**: the 4-state portal draws INSIDE `DrawPlayer2D` (the host) — the pass collects culled players (`culledPlayers`) then calls `DrawPortalSpritesPublic(camera)` in ALL modes (previously debug-only = portals vanished when the player was off-screen, a bug that was corrected).
- **DEBUG MODE (user: "give me a debug mode so I know which ones get culled")**: toggle **"Cull Debug" in the viewport toolbar** (red) → wires a per-sprite AABB: **RED = culled (not drawn), GREEN = rendered**; the button label becomes `Cull: N/M` (culled/total, live update). Implementation: `EditorObject.Show2DCullDebug` + the capture lists `Debug2DCullObjects/Debug2DCullCulled` (cleared & refilled each pass; empty between passes → boxes only on the active frame), `Draw2DCullDebugBoxes` depth-OFF (overlay), counters `EditorObject.Cull2DCulled/Total` (internal setter — the passthrough `EditorObjectManager.Cull2DCulled` is read-only, assignment = CS0200). An AMBER box on the camera = the camera is beyond the FAR plane (clip W ≤ 0) → every cull is correct (not a false positive).

## Post FX System Rules (Reactive Bloom + Auto Exposure):
- **One Shared Processor**: `PostFxProcessor.Shared` (singleton) — used by GameScene (`PostProcessStack.RunStack`) AND the editor's shared-FBO path (`SceneManager.ApplyInPlace`). Auto-exposure adapts continuously across paths. The GameScene-owned texture is NOT graded again in the editor path (double-grading).
- **Reactive Bloom Chain**: bright pass (threshold + soft knee) → 5-mip chain (½, ¼ …) via 13-tap downsample + ping-pong soften (2 round trips) → ADDITIVE Catmull-Rom upsample (`GL_BLEND` ONE/ONE, `u_MipScale` 0.8 low mip / 0.4 high). Mip 0's result = the final bloom. `BloomMips` (1-5, persisted) = the chain length.
- **NO glBlitFramebuffer for copy-back**: the blit wrapper is a SILENT NO-OP when the wgl pointers fail to load — the "works in the debug panel but not in the viewport" effect (the DoF and Post FX bugs both hit this). ALWAYS use a quad draw (passthrough shader, radius 0) to copy grading results into a scene texture/FBO.
- **NO Same-Texture Read+Write**: blur/sampling and writing the SAME texture = an UNDEFINED feedback loop. Always ping-pong via a scratch target (`_blurTexs[i]`).
- **Settings Reload on Project Open**: `PostFxSettings.Apply()` runs only once in Program.cs (exe fallback). The IDE MUST re-apply `PostFxSettings.Apply(SettingsSave.Load())` on project open/close — FilePath follows the project, so without a reload values always "revert to defaults" (saved to the project, loaded from the fallback). The panel re-syncs via `PostFxPanel.OnProjectChanged()`.
- **FX Debug Views**: `_fxDebugView` in ViewportPanel (the "FX Debug" button cycles Scene→Composite→Output→Luma→Mip 0-4, amber badge) + all targets in the FrameBuffer Debug panel (thumbnails via the `PostFxProcessor` debug surface). Falls back to the normal scene when the chain hasn't allocated / Post FX is off.
- **Persist**: all parameters (`Enabled`, `BloomIntensity/Threshold/SoftKnee/Mips`, `AutoExposure*`, `Gamma`, `Exposure`, DoF) stay symmetric via `PostFxSettings.Apply/Persist` → the project's `settings.json`.

## Day/Night Lighting Rules (Moonlight):
- **ONE night-brightness source of truth**: `Lights.cs` — `nightBrightness` (0.45) × `nightLight` (0.05,0.07,0.14). After ALL overrides (procedural + `LightColorOverride` + `SunBrightness`), `Update()` fades `lightColor` → moon tint via `finalNight = Smoothstep01(0.15, 0, sunDir.Y)`. Without this, the Light marker overwrites the day/night blend and night stays as bright as day (dark sky, bright terrain).
- **NEVER brighten night in the shader**: the old `moonColor` fallbacks in fragment_shader.glsl (0.08,0.12,0.25 when `length(lightColor)<0.1`) and (0.25,0.30,0.45) in gltf/impostor REPLACE the CPU's night color with a 2-3× brighter value — night looks like an overcast day. The shaders now pass `lightColor` through (the guard tint = the same dark value as the CPU).
- **Key light flip**: terrain (fragment_shader.glsl) already has `activeLightDir = mix(realSunDir, moonDir)`; PBR primitives (`objectPbr_fragment.glsl`) & impostors DON'T — without the manual flip `mix(sunDir, -sunDir, nightBlend)`, NdotL below-sun ≤ 0 = objects lose all direct light at night.
- **Moon disc (visual)**: the moon's brightness texture in sky_fragment.glsl is multiplied by 0.9 (was 1.25). Full per-Sky-object control via `SkySettings.Moon` (Brightness/Size/GlowRadius/Tint/Phase) — the realtime path.
- **Direction convention**: +Y = up (day) for `SunDirOverride` AND the procedural path — the `overrideNight > 0.5f → shadow uses -sunDir` gate in Lights.cs is correct, don't invert it.
- **Editor default 10:00**: `_editorLights` (BOTH sites in SceneManager.cs — the no-scene path AND the shared-FBO path) are created with startTime "10:00". The old default followed the real clock → opening the IDE at night = a pitch-dark viewport with no obvious time control. Sky objects (`SkyTimeOfDay` in the Inspector) still override per-scene.

## PBR Primitives (Box/Sphere/Plane) Rules:
- **Runtime type-agnostic**: the PBR render gate in `EditorObject.Draw` is ONLY `HasPbrMaterial && Shader.GetObjectPbrShaderProgram() != 0` — Plane goes through the same `DrawPbrPrimitive` as Box/Sphere (7 maps: albedo/normal/metallic/roughness/ao/height/emission, units 0-6, missing map = white texel + useX=0, shaders `objectPbr_fragment.glsl` + `vertex_shader.glsl`). NEVER add a `PrimitiveType is Box or Sphere` gate to the render path.
- **Single-quad plane artifacts (TWO mandatory fixes, both in place)**: plane = 1 CCW quad seen from above → (1) culled/missing when the camera looks from below; (2) with scene culling None, the bottom side shades with its up-facing normal = inverted normal-map relief + dark. Fix: `DrawPbrPrimitive` disables `GL_CULL_FACE` for Plane only (restored via `GL.IsEnabled` — honors scene culling None) + the shader `if (!gl_FrontFacing) norm = -norm;` BEFORE slope/TBN — flipping the norm also flips the T/B basis (cross-product derivatives against the norm) so both sides shade correctly. Box/Sphere unchanged (a closed mesh never sees its backface).
- **UI must follow the runtime**: PbrPanel `isPrimitive` and the Inspector "Texture Settings" MUST include `EditorPrimitiveType.Plane` — locking the UI to Box/Sphere means designers can't assign maps to a plane (the "PBR plane can't be used" symptom while the renderer actually works).
- **Shared tuning**: the per-object `TerrainPbr*` fields are used by ALL THREE types — the name is legacy, not terrain-specific.
- **Serializer**: `Pbr*Path` + `PbrTexSettings[7]` + tuning are already symmetric in SceneAsset — Plane PBR persists with no serializer change.
- **NEW shader file = MUST add CopyToOutputDirectory in the csproj**: a new `.glsl` file loaded via `SafeLoad("Artifacts/shaders/...")` needs a `<None Update="..."><CopyToOutputDirectory>Always</CopyToOutputDirectory></None>` csproj entry — an EMPTY entry (no child element) = NOT copied to bin → program = 0 → the draw path returns silently → objects DISAPPEAR WITHOUT ANY ERROR (symptom: feature ON = missing, OFF = normal; compile succeeds because the file is in the repo). VS F5 sometimes still works because cwd = project root (paths resolve into the repo), while the standalone exe from bin fails — the classic "works in VS, broken standalone". Verify output: `ls bin/Debug/net9.0/Artifacts/shaders/`.
- **"Missing object" diagnostics**: the PBR path NEVER returns silently — `DrawPbrPrimitive` writes one-shot `[PBR] {DISPLACED|STANDARD} shader program == 0` (latched `_warnedDispProgramZero` per object) when the program fails to load/link, and the chunked draw is wrapped in try/catch → `[PBR] Chunked draw FAILED ... → full-draw fallback` (geometry can never vanish without a console trace). When diagnosing "missing": read the Console panel first (search `[PBR]` + `[Shader]` + `[SHADER COMPILE ERROR]`), don't guess. **Real case that closed the "Displaced Plane Grid ON = missing" bug**: `pbrDisplace_vertex.glsl` had a comment line MISSING its `//` prefix on the continuation line ("...displacement\ntearing across...") → the line's first word became global-scope code → `[SHADER COMPILE ERROR] ... 'tearing' : syntax error` → program 0 → silent skip. That feature had NEVER worked since creation (not a regression). Rule: **new GLSL shaders MUST be smoke-test compiled** — a file that never compiled successfully only shows up in console logs, never as a build error; write multi-line GLSL comments without quotes and make sure EVERY comment line starts with `//`.
- **VERTEX DISPLACEMENT FORCED (user decision: "back to the start, force displacement to use vertex displacement") + its UI REPLACES the \"Height / Displacement\" POM tuning block in the PBR panel for PLANE** (user decision: "change image 1 into image 2"): a plane with a height source (`TerrainHeightSourcePath` filled OR `_sculptHeights != null`) ALWAYS displaces vertices — `PbrVertexDisplace` is NO LONGER consulted in any of the three gates (`RaycastPbrSurface` disp, dense-grid, program selection in EditorObject). UI (user decision "make it one new panel"): ALL terrain controls — the heightmap input, Terrain Geometry (Size/Base/Displace/Offset/Strength/Tiling/Segments/Chunks) + the Terrain Sculpt brush — live in a **separate PANEL** (`TerrainPanel.cs`, the "Terrain" menu); **the PBR panel keeps POM Height/Displacement + Calibration tuning for ALL primitives** (on a plane those calibrations also control the vertex-displacement detail set by the Terrain panel's Displace Height slider). Box/Sphere stay POM-only. **Consequence: plane elevation is RAW** — the shader's `terrainHeight()` skips calibration, so the CPU brushes (RaycastPbrSurface + TryGetPbrNormalizedHeight) MUST clamp raw WITHOUT `CalibrateHeight` (the brush floats half a height up if it stays calibrated); `CalibrateHeight` now has no caller on the plane path (it remains for Box/Sphere POM CPU sites if any). Plane POM-only DOES NOT EXIST: a plane's Height/Displacement slot = always geometry.
- **Chunked vertex grid (displaced plane)**: `PbrVertexSegments` (16..512, slider) + `PbrVertexChunk` (1..16, "Chunks per side" slider) on `EditorObject` — a chunk = a perChunk×perChunk vertex block (perChunk = segs/chunks, segs rounded to a chunk multiple) REORDERED into CONTIGUOUS per-chunk vertex ranges in ONE VBO (row-major, cz*chunks+cx) — per-chunk draw = a sub-range `GL.DrawArrays(start,count)` + per-chunk AABB frustum cull (`IsAABBInFrustum` Gribb-Hartmann from viewProj, lives in EditorObject). Shared edges are duplicated across chunks (identical positions, NO cracks; border normals do differ by 1 gradient sample — acceptable). Chunk AABBs inflate XZ ±0.5 + Y pad = `HeightAdvancePad·dispScale` (baseline scale-center: below it there's no displacement → edge culls never pop peaks). **STRUCT BY-VALUE TRAP**: chunk AABBs MUST be computed ANALYTICALLY from the chunk span (u0/v0 ± chunkSpan, mesh −0.5..0.5) — NEVER accumulate per-vertex bounds via `Vector3 min/max` parameters on the quad emitter: structs copy by value → updates write to the copy → the AABB stays inverted garbage (MaxValue/MinValue) → the frustum test rejects ALL chunks → the plane vanishes with displacement ON (symptom: "Displaced Plane Grid = off appears, on vanishes"). `PbrChunkCount<=1` or an empty height path → the plain 1-draw mesh fallback. **`u_dispGrid` TRAP**: the slope-shader uniform MUST use `PbrPlaneSegmentsBuilt` (what was actually built) NOT `PbrDisplaceSegments` (the legacy 256 constant) — wrong number = totally mis-scaled displacement slope. Persist: `PbrVertexSegments`/`PbrVertexChunk` (int? nullable, null = legacy) symmetric in SceneAsset + 3 SceneManagerPanel sites (save ×2 + load clamp) + clone manager. Live info in PbrPanel + Inspector (the "Displaced Plane Grid" section — ALWAYS shown for Plane, with the "Vertex Displacement" toggle INSIDE it so the section is never a dead end; Displace Height slider + Segments & Chunks per side + chunk/cull info + an amber warning when the height map is empty): chunk count, segs per chunk, cull count. **FATAL fallback-draw TRAP** (the "plane missing" bug): the pattern `if (PbrChunkCount > 1 && !DrawChunkedPlane(...)) { full draw }` DISCARDS the draw for a NON-chunked mesh (count==0 → condition false → 0 triangles = plane gone). Correct pattern: `drewChunks = count>1 && DrawChunkedPlane(...); if (!drewChunks) { full draw }` — full-draw MUST run whenever the chunked path didn't draw. **Restore culling**: capture `cullWasOn = GL.IsEnabled(GL_CULL_FACE)` BEFORE `GL.Disable` — checking IsEnabled AFTER the disable is always false, scene culling never returns.

- **Terrain Geometry (heightmap → mesh)**: the displaced-plane pipeline = a grayscale terrain generator — the height map's R channel sets vertex height (white = peaks), and normals are re-derived automatically from the height gradient in `pbrDisplace_vertex.glsl`. Plus **Height Offset** = `TerrainHeightOffset` (−250..250, uniform `u_dispOffset`) and **Displace Strength** = `TerrainHeightStrength` (0..3, uniform `u_dispStrength` — reshapes RAW elevation around mid-gray: 0 flat, 1 as-authored, >1 sharper peaks/deeper valleys) — all SEPARATE TERRAIN FIELDS; slope/normal read the SAME `displaceWorld()` so lighting stays consistent; the chunk AABB pad uses the real max = base + ½·disp + |offset| (dispHeightNorm arg = 1.0); SEPARATE from `PbrVertexDisplaceScale`/`PbrVertexOffset` which are now legacy PBR-only (a terrain-driven plane reads the terrain fields; legacy migration: SceneAsset −1 sentinel → falls back to the old PBR values on load, save ×2 + load clamp; the `u_dispScale`/`u_dispOffset` uniforms upload per-source in `DrawPbrPrimitive`); Resolution = `PbrVertexSegments` — the dense-grid gate `PbrVertexChunk > 1 || TerrainHeightSourcePath != ""` makes the Segments slider APPLY without needing chunking. The chunk AABB pad + the plane's picking proxy AABB include the extent = `TerrainDisplacementExtent` (scale + |offset|) so offset terrain neither culls at edges nor fails picking.
- **Terrain heightmap SEPARATE from PBR height (unit 15 vs unit 5)** (user decision): `TerrainHeightPath` (EditorObject, back-field + the `_terrainHeightTex` texture lazy-loaded in DrawPbrPrimitive) = the BASE elevation/shape → RAW 0..1 vertex displacement WITHOUT calibration (`displaceSource()` branch `u_terrainDisplace`); `PbrHeightPath` = the POM DETAIL map (fragment unit 5) — two DIFFERENT sources. `TerrainHeightSourcePath` = the effective source (Plane-only fallback to `PbrHeightPath` for legacy scenes that stored elevation in the PBR slot — every elevation reader MUST use this: dense gate, displaced program gate, `HasPbrMaterial`, panel status). POM detail fallback: when elevation exists but the POM slot is empty, the elevation texture is ALSO bound to unit 5 (`UseMaps[5]=1`) so POM reads real height data (not a white texel → phantom bumps); relief shadows come alive too. ## PBR Splat Terrain (paintable multi-texture plane) Rules:
- **Inside objectPbr, NOT a separate shader — but through the VARIANT program `#define TERRAIN_SPLAT`**: the splat block lives INSIDE `objectPbr_fragment.glsl` (shared by Box/Sphere/Plane) wrapped in `#ifdef TERRAIN_SPLAT` (splat samplers + the blend block in main()). `Shader.cs` compiles TWO additional programs from the SAME source via prefix defines (injected AFTER the `#version` line — `ShaderHelpers.LoadShader(vertex, fragment, fragmentPrefix)`): `GetObjectPbrSplatShaderProgram` + `GetObjectPbrSplatDisplaceShaderProgram`. **WHY THE VARIANT IS MANDATORY**: `GL_MAX_TEXTURE_IMAGE_UNITS` = 32 on the target GPU — base objectPbr has 17 samplers (7 maps + 3 CSM + 7 local-light shadows) + 25 splat = 42 > 32 → linking FAILS with "Number of sampler exceeds the limitation" → the whole splat block was once DELETED as "dead code" (commit 82e62b5) while its C# was still rebuilt → every `GetUniformLocation("u_splat*")` = −1 → paint/bands NEVER appeared in the viewport even though the TGA bake was correct. The splat variant trades the 7 local-light SHADOW samplers for 21 splat samplers (weight + albedo/normal/metal/rough/AO ×4 layers; the per-layer POM height samplers are DROPPED) = 31 ≤ 32. `DrawPbrPrimitive` picks the variant per plane when splat state exists (`_splatField || _splatFieldForBands || _splatMapPath`) + falls back to the regular program when variant == 0 (one-shot warning). Point/Spot lights still ILLUMINATE splat planes, they just cast no shadows. `Tools/ShaderSmokeTest` now compiles 4 objectPbr programs (base/displaced/splat/splat-displaced) + prints GL_MAX_TEXTURE_IMAGE_UNITS — it MUST be green before committing shader edits. `splatMerge()` mixes PBR params per layer AFTER the POM march, BEFORE albedo tuning; gate `u_splatActive`; layer 0 = the PBR base material — an unpainted plane renders identically to the regular path (zero regression).
- **Splat texture units** (bound in `DrawPbrPrimitive`): 10 = the RGBA8 weight map (`u_splatWeights`), 11-14 albedo, 21-24 normal, 31-34 metal, 41-44 rough, 51-54 AO, 61-64 height ×4 layers (the layer-0 slot = the base PBR maps — never double-bind the same unit). All-empty slots → white texel; the presence gates `u_splatHasAlbedo/Normal/Metal/Rough/Ao/Height` are FLOAT vec4s → MUST be ONE `Uniform4f` per gate (the old scheme of 4× `Uniform1i(loc+i)` = a silent double bug: glUniform1i on a vec4 location = GL_INVALID_OPERATION → presence always 0 → layer textures never sampled (the tint color shows); loc+i on a non-array vec4 lands in a DIFFERENT uniform → a corrupted sampler/random texture) — EMPTY layer slots must get weight-0 (remainder renormalized), not white/black strips. `u_splatTint[l]` = the fallback for layers without albedo (layer 0 = obj.Color). **"PAINT TILES" GOTCHA**: the splat weight map MUST sample RAW `TexCoord` (1:1 with the 256² field) — it used to go through the tiled `uvAlbedo`, repeating the stroke once per Map Tiling tile. Layers 1-3 use their OWN per-layer tiling `u_splatLayerTiling[l]` (`SplatLayerTiling`, sliders in the TerrainPanel's Layer textures, independent of Map Tiling; layers 1-3 also skip the POM shift) — layer 0 keeps base UV + POM shift. Splat TGA byte0 = layer2 (RED in viewers), byte1 = layer1 (GREEN) — dump the channels first before diagnosing a "wrong layer".**
- **Splat field** = `TerrainSplatField` (Engine/Objects/TerrainSplatField.cs): CPU 256² RGBA, weights sum=1 per texel; per-layer Paint/Erase/Smooth brushes (`SplatApply`, frame-batched `frameStamp`), 40-snapshot undo (`SplatUndo/Redo`), a GL_RGBA8 dirty-rect texture via `TexSubImage2D`, bake TGA RGBA 32-bit `Artifacts/Terrain/<scene>/<object>_splat.tga` (BGRA on disk — TGA stores BGRA) → `SplatMapPath`. A field loaded from file gets `FlushTexture()` ONCE so `GpuTexture != 0` (the draw gate). Brush coordinates are plane-LOCAL, same as sculpt. **BUG "TGA correct, nothing in 3D" (fixed): `EnsureTexture()` used to call `TexImage2D`+`TexParameter` WITHOUT `GL.BindTexture` first (GenTextures ≠ auto-bound) — the upload landed on whatever texture was bound, the weight texture itself had NO storage → incomplete sampling = black → `splatSum=0` → the shader fell back to all-layer-0 → paint invisible in the viewport even though the CPU field + TGA bake were correct (sculpt passed because `TerrainHeightfield.EnsureTexture` does bind). Now EnsureTexture binds first + `UploadWhole()` binds its own. Sibling case: `FromFile()` used to NOT mark a dirty rect → an eager `FlushTexture()` after a failed decode returned false without creating a GPU texture → `GpuTexture==0` → the `splatActive` gate false → paint from a RELOADED scene didn't show; FromFile now calls `MarkWholeDirty()`. GENERAL RULE: every `GenTextures` MUST be immediately followed by `BindTexture` before ANY `TexImage2D/TexParameter/TexSubImage2D` — the GL wrapper does not auto-attach new handles.
- **SLOPE layer (PBR)**: the TerrainPanel's "Auto layer from slope" — layers 1-3 automatically appear on STEEP surfaces via `TerrainSplatField.ComputeSlopeWeights` (a smoothstep(threshold, +fade, 1−N.Y) mask from the combined base+delta elevation, world-unit gradient, terrain tiling; sum-preserving fold; paint wins). Recompute is AMORTIZED (`_splatBandsPending`, max 1× per draw) — elevation/BaseHeight/Offset/tiling/band setters trigger `InvalidateSplatBands()`. Bands NEVER overwrite a field decoded from a splat file (`_splatLoadedPath == _splatMapPath` → skip; the stored weights ALREADY contain the paint-over bands). ## Per-Sprite Glow Rules (Emissive Post-FX):
- **Mechanism**: per-sprite emissive boost — the sprite's vertex color is multiplied by the boost so ONLY bright pixels (fire/lava/candles) cross the Post FX bloom threshold; dark pixels (body, wood) stay normal. No mask texture needed. REQUIRES Post FX ON.
- **NO shader uniform**: the map2d shader has no tint uniform — boost/tint/flicker are BAKED into the vertex tint (`aTint`) in DrawSprite2D/DrawPlayer2D. Never add a GL.Uniform4f.
- **Fields**: `Sprite2DGlow`/`Player2DGlow` (0-1), `Sprite2DGlowColor`/`Player2DGlowColor` (Vector3 — normalized so the brightest channel = 1 at render time, meaning even dark colors yield the full hue), `Sprite2DGlowFlicker`/`Player2DGlowFlicker` (bool).
- **Flicker**: `ComputeGlowBoost` — 3 out-of-phase sines (irrational frequencies) over `Glfw.PeekTime()` (absolute time), seeded per object from the NAME hash (FNV-1a) → two fires never sync, amplitude ~±22% around the Glow value. Frame-gated via `Glfw.FrameId` — sample once per frame so the editor pass + the second pass stay consistent (same pattern as the animation clock).
- **Glfw.PeekTime()**: a read-only `glfwGetTime()` accessor — safe to call many times per frame, does NOT shift the shared clock (only SceneManager.Run may GetDeltaTime).
- **Inspector**: slider "Glow (bloom)", color picker "Glow Tint" (e.g. blue = blue fire), checkbox "Flicker" — ada di bagian Sprite2D DAN Player2D.
- **Persist**: all fields symmetric via `EditorObjectData` (Glow, GlowColorX/Y/Z, GlowFlicker) in the scene `.ing`.

## Binary JSON Cache (Loading Speed) Rules:
- **ONE CHOKE POINT**: all binary sidecar access goes THROUGH `Helpers.BinaryObjectCache` (`Engine/Helpers/BinaryObjectCache.cs`) — NEVER read/write `.cache/*.json.bin` files directly. API: `TryLoad<T>(jsonPath)` (null = fall back to the JSON), `TryWrite<T>(jsonPath, obj)`, `SetEnabled(bool)` kill switch, `LastLoadWasBinary` telemetry (internal set; TryLoad resets it itself at the start — NEVER assign it from outside, CS0200).
- **UNBREAKABLE CONTRACT (fallback-by-construction)**: JSON stays the SOURCE OF TRUTH — the sidecar is only an accelerator. `TryLoad` NEVER throws: magic/version/layout/type-mismatch/stamp failures → return null **SILENTLY** (no log — a v1 sidecar or an old layout is rejected in the header BEFORE the payload is touched, so there is NEVER a `[BinCache] cache invalid` spam); a `[BinCache] ...` log only appears when an exception hits mid-payload-decode (a corrupt file) → the caller parses the JSON normally (wiring pattern: `var cached = BinaryObjectCache.TryLoad<T>(path); var data = cached ?? JsonSerializer.Deserialize<T>(json, Options);`). A failed TryWrite = a silent no-op (the JSON save still runs). NEVER build a load path that DEPENDS on the cache.
- **AUTOMATIC STAMP INVALIDATION**: the sidecar header = [magic 0x4E494244][ver=2][rootTypeName][layoutId u64][jsonLen][jsonHash FNV-1a][jsonMtimeTicks] — compared against the JSON on disk at TryLoad time; editing the JSON (len/hash/mtime change) = an invalid sidecar → fall back to the JSON + the next TryWrite re-stamps. Root type guard: rootTypeName ≠ typeof(T).Name → reject (a mixed-type cache can never be used). **LAYOUT GUARD (the reason for ver=2)**: the binary payload is POSITIONAL without names in alphabetical property order — if a DTO changes (e.g. a `PatternActions` field is added), an old sidecar decodes askew (an Int32 lands on a string property → ArgumentException → log spam on every load). `layoutId` = an FNV-1a 64 hash of the type's recursive member layout (`LayoutId(Type)`, per-type cache; cycle → `ref;`) — a different layout / version 1 → rejected silently before decode. Old v1 sidecars are automatically rejected by the version bump.
